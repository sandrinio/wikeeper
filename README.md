**A Karpathy-style LLM wiki that your AI coding agent keeps.**

---

Most AI agents start every session from zero. wikeeper gives yours a memory it maintains itself: a folder of plain, interlinked markdown pages built from the links, PDFs, documents and conversations you hand it, with every fact traced back to its source.

One command installs everything the agent needs (instructions, skills, page templates and a CLI) into any repository. It works with **Claude Code**, **OpenAI Codex** and **Google Antigravity**.

## How it works

```
you share a file, a folder, a link, or just say something worth keeping
        │
        ▼
wikeeper ingest start   ── pre-hook: duplicate check · permission · store original
        │
        ▼
agent triages & extracts   ── reads the wiki index, applies your capture rules,
        │                     produces a list of cited facts
        ▼
writer agent updates pages ── one source at a time; contradictions flagged, never overwritten
        │
        ▼
wikeeper ingest finish  ── post-hook: diff · validate citations · index & log · report
```

- **The agent thinks, the CLI enforces.** The CLI makes no LLM calls and needs no API keys. It handles the parts that must be reliable: permissions, raw-source storage, diffs, the index and log, search and lint. Your agent does the reading and writing.
- **Every fact is cited.** Originals are kept unchanged in `raw/`; each claim on a page links to the source it came from.
- **You decide what's captured.** `kb_instructions.md` holds the capture rules for your purpose. The agent proposes additions as it meets new kinds of information; you approve them.
- **Read once.** Whoever already has a source in context extracts from it. Large batches are split across small, cheap sub-agents; one writer agent updates the pages.
- **Your knowledge is yours.** `update` only replaces wikeeper's own files. `remove` never deletes knowledge unless you ask for `--purge`.

## Ingest permissions

| Mode | Behaviour |
|---|---|
| `ai` | The agent decides what to ingest. |
| `ask` | Every ingest needs your approval. |
| `whitelist` | Listed sources are allowed; everything else is denied. |

After every ingest you get a short report of what was ingested and which pages changed, generated by the CLI from the actual diff.

## Purposes

The first built-in profile is **Management**: team, projects, risks, decisions and a glossary, plus a short private profile of you, so the agent can address you by name and recognise you in meeting notes ("Action: Alex to send budget" becomes *you owe the budget*).

## Planned commands

| Command | Purpose |
|---|---|
| `wikeeper init [--profile management]` | Scaffold `.wiki/`, wire up your agents |
| `wikeeper update` / `remove [--purge]` | Lifecycle |
| `wikeeper ingest start · plan · facts · apply · finish · abort` | Gated, three-phase ingest |
| `wikeeper search` | Full-text and structured search (`wiki_search`) |
| `wikeeper read <file\|url>` | Markdown for formats the agent can't read itself (DOCX, PDF, web pages) |
| `wikeeper lint` · `status` · `doctor` | Health checks |

Every command will support `--json`, because the main user of the CLI is your agent.

## Agent support

| | Claude Code | Codex | Antigravity |
|---|---|---|---|
| Instructions | `CLAUDE.md` | `AGENTS.md` | `AGENTS.md` / `GEMINI.md` |
| Skills | `.claude/skills/` | `.agents/skills/` | `.agents/skills/` |
| Sub-agents | `.claude/agents/` | `.codex/agents/` | `.agents/agents/` |

wikeeper injects a short, clearly marked block at the top of your agent files and never modifies a file that already has it.
