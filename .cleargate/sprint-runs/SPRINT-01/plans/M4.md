- **`init(ctx)`.** `flags.agents` is `string | undefined` (commander `--agents <list>`):
  1. `lines = ctx.options.interactive ? createLineReader(ctx.options.io.stdin) : null`. Everything below runs in `try { … } finally { lines?.close() }`.
  2. `existing = await detectAgentFiles(root)`. Then `r = await resolveAgents({ flag: flags.agents, config: ctx.config, isTTY: ctx.options.interactive, json: ctx.options.json, existing, ask: lines ? createAskAgents({ stderr: io.stderr, lines }) : async () => [] })`. If `r.status === "needs_input"`, `throw needsInputError(r)` (exit 5).
  3. If `r.source !== "config"`, call `await setConfigValue(root, "agents", r.agents)`. Not reported: core owns `.wiki/config.yml`.
  4. `pruneDeconfigured(ctx, agents, existing)` (shared with `update`, see below).
  5. `res = await installAgentAssets({ root, agents, manifest, templatesDir: ctx.options.templatesDir, config: ctx.config })`. It throws `install_conflict` before writing anything, so it runs **before** any block write. Merge `created/replaced/skipped/warnings`. For each `res.dirs` path with no existing entry, push `{ path, sha256: null, kind: "dir", created: true }`.
  6. Blocks: `block` = the template text. For each `t of resolveTargets(agents, existing)`: `{ status, created } = await injectIntoFile(path.join(root, t.path), block)`. injected+created → `created`; injected → `replaced`; skipped → `skipped`. Upsert `{ path: t.path, sha256: null, kind: "block", created: old?.created ?? created }`. **Keep the old `created`**, or a second run flips it and breaks check 2.
  7. `state = { agents, lines }`. For each `ext of AGENTS_EXTENSIONS`, `await ext.init?.(ctx, state)`, merging its report.
  8. Return the merged report. Lists are unsorted; core sorts them.
- **`update(ctx)`:** `agents = ctx.config.agents.filter(isAgentName)`. Unknown names produce the warning `config agents: unknown "<x>" ignored`. If `agents` is empty, return `{}`. Otherwise run `pruneDeconfigured`, then step 5 above with `ctx.options.templatesDir`, then the extensions' `update` with `lines: null`. **Never** touch `block` entries or files (D-11).
- **`pruneDeconfigured(ctx, agents, existing)`:**
  - **Skill, sub-agent and link entries:** an entry is dropped when its `agent` is set, is not `SHARED_AGENT`, and is not in `agents`. For `skill`/`subagent`: if the file hash equals `sha256`, `rm`; otherwise keep the file and warn `<path> was edited; left in place`. For a `link` whose `lstat` shows a symlink, `unlink`. Drop the entry either way; deleted paths go to `removed`.
  - **Block entries:** a block entry whose path is not in `resolveTargets(agents, existing)` is stripped like `remove` step 2, and its entry is dropped.
  - **Dirs:** finish with the empty-dir pass from `remove` step 4, applied only to `dir` entries. A removed dir's entry is dropped.
  - On a second `init` with the same agents this does nothing, which keeps check 2 at 0 bytes.
- **`remove(ctx)`:** the manifest is read-only. Core deletes it afterwards.
  1. Extensions run first, in **reverse** `AGENTS_EXTENSIONS` order: `ext.remove?.(ctx, { agents, lines: null })`.
  2. For each `block` entry: `stripFromFile(abs)`.
     - `stripped`: re-read the file. If `created === true` and the text minus a BOM is `trim() === ""`, `rm` it and list `<path>` in `removed`. Otherwise list `<path>#wiki-block` in `removed`.
     - `absent`: warning `<path>: WIKI block already gone`.
     - `malformed`: warning `<path> has WIKI:START without WIKI:END; left unchanged`.
     - Text outside the markers stays byte-identical (C5 guarantees it).
  3. `skill`/`subagent` entries → `rm(abs, { force: true, maxRetries: 3 })`, and the paths that existed go to `removed`. `link` entries → if `lstat` shows a symlink, `unlink` → `removed`; if it is a real directory, add it to `kept` with a warning. **Never** act on `hook`/`rule` (owned by extensions) or on core kinds (`system`, `file`, `gitignore`).
  4. `dir` entries, deepest first (segment count descending, then path descending): `rmdir`. ENOTEMPTY/EEXIST → `kept`. ENOENT → ignore.

- **`guard-command.ts`** (R5 as clarified):
```ts
export type GuardForm = "path" | "local" | "npx";
export interface ResolveGuardOptions { root: string; env?: NodeJS.ProcessEnv; platform?: NodeJS.Platform; isExecutable?: (file: string) => boolean }
export function resolveGuardForm(o: ResolveGuardOptions): GuardForm;
export function guardCommand(form: GuardForm, agent: AgentName, packageVersion: string): string;
```
  - **Resolution, first match wins:**
    1. **`path`:** some `PATH` entry (split by `path.delimiter`) holds an executable `wikeeper`. On win32 the candidates are `wikeeper` + each `PATHEXT` extension, compared case-insensitively. **Skip any PATH entry whose last two segments are `node_modules/.bin`:** npm/npx prepend these to PATH while `npx wikeeper init` runs (local project bins, or the `_npx/<hash>` cache). They are not there when the agent later runs the hook.
    2. **`local`:** `<root>/node_modules/.bin/wikeeper` exists (on win32, `wikeeper.cmd`).
    3. **`npx`.**
  - `isExecutable` defaults to `statSync(f).isFile() && (win32 || accessSync(f, X_OK) succeeds)`.
  - **Rendered command:** `<prefix> hook guard --agent <a>`. The `<prefix>` is:

    | form | claude | codex | antigravity |
    |---|---|---|---|
    | path | `wikeeper` | `wikeeper` | `wikeeper` |
    | local | `"$CLAUDE_PROJECT_DIR"/node_modules/.bin/wikeeper` | `"$(git rev-parse --show-toplevel)"/node_modules/.bin/wikeeper` | same as codex |
    | npx | `npx -y wikeeper@<packageVersion>` | same | same |
  - **Why `local` looks like this:**
    - The research's "Hook command resolution" table documents `$CLAUDE_PROJECT_DIR` for Claude and the git-root form for Codex. Both are repo-relative, so a committed settings file works for every clone. An absolute path would leak one machine's layout into git.
    - Antigravity has no documented variable. It reuses the git-root form because its hooks run in the workspace (`workspacePaths`). If that turns out wrong, the hook fails to start, Antigravity reports the error and continues (App v2.12.0), so it fails open, and `antigravity-trust` tells the user to verify it.
    - The prefix is version-independent, so Codex's trust hash survives `update`. Only the `npx` form changes on update, which `codex-trust` already warns about.
  - **Argument parsing:** the commands end exactly in `hook guard --agent <a>`, matching 002-05 (`--agent [name]`, unknown args allowed). Never append `--json` or any other flag.
- **Entry shapes (research §C, with the clarified matchers). `CMD(a)` is `guardCommand(form, a, packageVersion)`:**

  | Agent | File | Container | Owned value | Identity (manifest `identity`) |
  |---|---|---|---|---|
  | claude | `.claude/settings.json` | `hooks.PreToolUse[]` | `{"matcher":"Edit\|Write\|MultiEdit\|NotebookEdit","hooks":[{"type":"command","command":CMD("claude")}]}` | `hooks.PreToolUse[guard:claude]` |
  | claude | same | `permissions.allow[]` (ai) | `"Bash(npx wikeeper *)"`, `"Bash(wikeeper *)"` | `permissions.allow[<rule>]` |
  | claude | same | `permissions.ask[]` (ask) | `"Bash(npx wikeeper ingest start *)"`, `"Bash(wikeeper ingest start *)"` | `permissions.ask[<rule>]` |
  | codex | `.codex/hooks.json` | `hooks.PreToolUse[]` | `{"matcher":"apply_patch","hooks":[{"type":"command","command":CMD("codex"),"timeout":30}]}` | `hooks.PreToolUse[guard:codex]` |

  (`\|` is a table escape; the strings contain a bare `|`.) `whitelist` adds no rules and creates no `.rules` file.
  - **Manifest entries:** `{ path, sha256: null, kind: "hook" | "rule", agent, identity, created }`. Hook groups and the `wikeeper-guard` key use `hook`; permission strings and `.rules` lines use `rule`. `created` means wikeeper created the file; keep the old value on re-runs.
  - **Backups:** a `.bak` that wikeeper wrote is recorded as `{ path: "<file>.bak", sha256: null, kind: "hook", agent, identity: "backup" }`. A user's pre-existing `.bak` is never recorded and never touched.
  - **Dirs** wikeeper creates (`.codex/rules`, maybe `.claude`, `.codex`, `.agents`) are recorded as `{ kind: "dir", created: true }`. 002-04's remove step 4 deletes them; enforce never calls `rmdir`.
  - **Identity → matcher (removal works from the manifest alone):**
    - `backup` → the backup.
    - `/^(.+?)\[(.*)\]$/` → a container path plus a selector. Selector `guard:<a>` matches an array element that is a plain object whose `hooks[]` contains a `command` string ending in ` hook guard --agent <a>`; any guard form matches. Any other selector matches an array element `===` the selector.
    - No brackets → a root key (Antigravity).
    - A matching element that the manifest does not list (for example, hand-added) is **adopted**: replaced in place and recorded. This is how dedupe works.
- **`json-merge.ts`** (R6):
```ts
export type JsonObject = Record<string, unknown>;
export interface JsonDoc { abs: string; rel: string; existed: boolean; original: Buffer | null; value: JsonObject; indent: string; eol: "\n" | "\r\n"; bom: boolean; finalEol: boolean }
export function loadJsonDoc(abs: string, rel: string): Promise<JsonDoc>;       // strict; ENOENT → {} with existed:false, indent "  ", eol "\n", finalEol true
export function serializeJsonDoc(doc: JsonDoc, value: JsonObject): string;
export interface SaveResult { written: boolean; backup: string | null }        // backup = posix rel of a .bak WE wrote
export function saveJsonDoc(doc: JsonDoc, next: JsonObject): Promise<SaveResult>;
export function mergeJsonFile(abs: string, rel: string, mutate: (v: JsonObject) => void): Promise<SaveResult>; // load + structuredClone + mutate + save
export function upsertArrayItem(root: JsonObject, container: readonly string[], match: (el: unknown) => boolean, value: unknown, rel: string): void;
export function removeArrayItems(root: JsonObject, container: readonly string[], match: (el: unknown) => boolean): boolean;
export function settingsError(rel: string, detail: string): WikeeperError;      // ExitCode.ERROR, code "settings_invalid", details { file: rel, error: detail }
```
  - **Strict parse:** decode with `TextDecoder("utf-8", { fatal: true, ignoreBOM: true })`, strip the BOM, then `JSON.parse`. Failure, a 0-byte file, or a root that is not a plain object → `settingsError(rel, msg)`. The message is `<rel> is not valid JSON: <msg>; nothing was changed`.
  - **Format detection:** `indent` = the whitespace of the first indented line (default 2 spaces). `eol` = the first line break. `finalEol` = whether the text ends with a newline.
  - **Serialize:** `JSON.stringify(v, null, indent)` with `\n` replaced by `eol`, a final EOL when `finalEol`, and the BOM re-added.
  - **Key order:** `JSON.parse`/`stringify` keep insertion order, except integer-like keys, which JS hoists (accepted). New containers are appended last.
  - **Save:**
    - `isDeepStrictEqual(parse(original), next)` → no write. Unchanged files never get reformatted.
    - Otherwise, before the first change to a file that existed: `copyFile(abs, abs + ".bak", COPYFILE_EXCL)`. EEXIST means the `.bak` is not ours: `backup: null`, continue.
    - Then write.
  - **`upsertArrayItem`:**
    - Missing containers are created: an object for a middle segment, an array for the last.
    - An existing container of the wrong type → `settingsError(rel, '"hooks.PreToolUse" is not an array')`.
    - The first match is replaced in place when not deep-equal; later matches are removed (dedupe). No match → push.
  - **`removeArrayItems`:** deletes the matches, then prunes containers on that path that are now empty (`[]`/`{}`), deepest first. An empty container on wikeeper's path is semantically the same as an absent one.

## Cross-story risks
1. **Extension order inside `agents.init`.** Enforce runs after blocks, skills and sub-agents are written, so the `settings_invalid` exit 1 leaves those files on disk (M2 open decision 2, no rollback). A re-run is safe. The Gherkin only requires the settings file to be byte-identical.
2. **`upsertManifestEntry` drops every entry with the same path.** 002-04 may use it for `block` and `dir` entries. 002-06 must never use it: `.claude/settings.json` carries several `hook`/`rule` entries plus their `.bak`.
3. **Kind ownership.** Core: `system`/`file`/`gitignore`. 002-04: `block`/`skill`/`subagent`/`link`/`dir`. 002-06: `hook`/`rule`, plus the `dir` entries it records (deleted by 002-04's generic dir pass). 001-06 throws `unsafe_path` for a `file` entry outside `.wiki/`, so the `.bak` is recorded as kind `hook`.

5. **One stdin reader.** The agents prompt and the enforce prompt share `state.lines`. A second `createInterface` on the same stdin loses buffered lines (`Readable.from(["1,2\n","y\n"])` arrives as one chunk).
6. **Goal check 1 command** is `init --json --agents claude,codex,antigravity`; plain `--json` exits 5 by design (sprint-context clarification).
7. **`npx`-injected PATH.** Without the `node_modules/.bin` skip, `npx wikeeper init --enforce` writes bare `wikeeper`. The hook later fails to start, and Claude/Codex silently fail open.
