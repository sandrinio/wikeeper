## C4 — exact types M3 compiles against (`src/core/integrations.ts`, `src/core/gitignore.ts`)
FROZEN means the name and parameters stay exactly as in waves.json. **NEW** means it must be added to the C4 skeleton (001-04 owns it, and M2.md must agree; see open decision 3).
```ts
// src/core/integrations.ts
import type { CliIO } from "./output.js";
import type { WikeeperConfig } from "./config.js";
import type { ResolvedPaths } from "./paths.js";
import type { Manifest } from "./manifest.js";
export type IntegrationPhase = "init" | "update" | "remove" | "doctor";     // NEW name for the frozen literal union
export type DoctorSeverity = "ok" | "info" | "warning" | "error";          // NEW ("info": 002-04 codex-trust, 002-06 notes)
export interface DoctorCheck {                                              // NEW; rendered by 001-07, produced by 002-04/002-06
  id: string;          // stable kebab-case: "manifest-drift", "agent-block-missing", …
  severity: DoctorSeverity;
  message: string;     // one line, no trailing newline
  fix?: string;        // one imperative line, e.g. "run wikeeper init"
  file?: string;       // posix path relative to root, when the finding concerns one file (002-04 R5)
}
export interface IntegrationOptions {                                       // NEW: the "options" member of the frozen ctx
  flags: Readonly<Record<string, unknown>>; // the command's commander opts verbatim (init: profile/agents/yes/enforce; remove: purge/confirm)
  json: boolean;                            // OutputContext.json
  interactive: boolean;                     // ctx.isTTY && !ctx.json; prompt only when true
  io: CliIO;                                // stdin/stderr/cwd for prompts; handlers never write results to stdout
  manifest: Manifest;                       // see "manifest contract" below; never null
  templatesDir: string;                     // templates root (holds system/); update tests inject a fixture
  packageVersion: string;                   // version from <findPackageRoot()>/package.json
}
export interface IntegrationContext {                                       // NEW name for the frozen { root, paths, config, options }
  root: string; paths: ResolvedPaths; config: WikeeperConfig; options: IntegrationOptions;
}
export interface PhaseReport {                                              // NEW; posix paths relative to root
  created?: string[]; replaced?: string[]; skipped?: string[]; removed?: string[]; kept?: string[]; warnings?: string[];
}
export type PhaseHandler  = (ctx: IntegrationContext) => PhaseReport | void | Promise<PhaseReport | void>; // NEW
export type DoctorHandler = (ctx: IntegrationContext) => DoctorCheck[] | Promise<DoctorCheck[]>;          // NEW
export interface Integration {                                              // NEW name for the frozen object shape
  name: string; init?: PhaseHandler; update?: PhaseHandler; remove?: PhaseHandler; doctor?: DoctorHandler;
}
export interface IntegrationRunResult {                                     // NEW; every array present, possibly empty
  created: string[]; replaced: string[]; skipped: string[]; removed: string[]; kept: string[]; warnings: string[];
  checks: DoctorCheck[];
}
export function registerIntegration(integration: Integration): void;                                              // FROZEN
export function runIntegrations(phase: IntegrationPhase, ctx: IntegrationContext): Promise<IntegrationRunResult>; // FROZEN params; NEW return type
export function resetIntegrations(): void;                                  // NEW (001-04 task "reset-for-tests"); clears the registry
```
**Semantics of the 001-04 body that M3 relies on:**
- `registerIntegration` appends to the registry. Registering a name twice throws an `Error` with `code: "E_INTEGRATION_DUPLICATE"`.
- `runIntegrations` awaits handlers one at a time. The order is registration order for `init`, `update` and `doctor`, and **reverse** registration order for `remove`. A missing handler is skipped. Report arrays are concatenated in run order; callers sort them.
- In `init`, `update` and `remove`, a handler that throws stops the run and the error propagates.
- In `doctor`, a handler that throws becomes the check `{ id: "integration-<name>", severity: "error", message: "doctor handler failed: <message>" }`, and the run continues.
- Kind ownership: core (001-04/05/06) owns the kinds `system`, `gitignore` and `file`; integrations own every other kind. Core never deletes or rewrites an entry of an integration kind. Integrations never touch core kinds.

**Manifest contract (`options.manifest`), per phase:**

| Phase | What handlers receive | What handlers may do | Who writes or deletes the manifest |
|---|---|---|---|
| `init`, `update` | The working manifest. Core has already set its `system` entries. | Upsert or delete their own kinds in `manifest.files`, in place. | Core writes it after the run. |
| `remove` | The manifest as read from disk. | Read only. | Core deletes it after the run. |
| `doctor` | The manifest as read from disk, or `{ package_version: "", files: [] }` when not initialised. | Read only. | Nobody; doctor never writes. |

**C4 skeleton.** Per waves.json, the bodies are no-ops. The stub `runIntegrations` must resolve to the all-empty `IntegrationRunResult`, never `undefined`. `resetIntegrations` is also a no-op.
```ts
// src/core/gitignore.ts
export const GITIGNORE_BLOCK_START = "# >>> wikeeper >>>";                                  // FROZEN
export const GITIGNORE_BLOCK_END = "# <<< wikeeper <<<";                                    // FROZEN
export function applyManagedBlock(text: string, entries: readonly string[]): string;        // FROZEN name/params; param + return types proposed (M2 confirms)
// appended by STORY-001-06 in its own branch (NOT in the C4 skeleton):
export type GitignoreStripStatus = "stripped" | "absent" | "malformed";
export function stripManagedBlock(text: string): { text: string; status: GitignoreStripStatus };
```
**Round-trip invariant.** 001-04 builds it and 001-06 tests it: for any `t` that is empty or ends with an EOL and contains no block, `stripManagedBlock(applyManagedBlock(t, e)).text === t`. This requires `applyManagedBlock` to behave as follows:
- **No block present:** return `t + block`, where `block` is the START line, the entry lines and the END line, each ending with `t`'s EOL (LF when `t` has no line break). Add no blank separator line. If `t` lacks a trailing EOL, append one EOL first; this degenerate case is not restored by strip.
- **Block present:** replace the START…END lines in place.
- **Manifest entry:** `{ path: ".gitignore", sha256: null, kind: "gitignore", created }`, where `created` is true when init created the file.

### STORY-001-05 — `wikeeper update`
STORY-001-05 advances the goal by replacing only the manifest-tracked `.wiki/system/**` files and backing up local edits first, so `update` changes 0 user-owned files (Goal check 3).
- **Files (§3.1):** `src/commands/update.ts` (new), `test/update.test.ts` (new), `src/program.ts`. QA-Red writes `test/update.red.node.test.ts`.
- **`src/program.ts`:**
  - Add `import { updateCommand } from "./commands/update.js";` to the command-import region.
  - Append `  updateCommand,` as the last element of `defaultCommands`.
- **Exports:**
```ts
export interface UpdateResult { replaced: string[]; added: string[]; removed: string[]; backed_up: string[]; warnings: string[] }
export interface UpdateDeps { templatesDir?: string; packageVersion?: string; now?: () => Date }
export function runUpdate(root: string, run: Pick<IntegrationOptions, "flags" | "json" | "interactive" | "io">, deps?: UpdateDeps): Promise<UpdateResult>;
export function formatBackupStamp(d: Date): string;              // UTC "YYYYMMDDHHmmss", digits only
export function createUpdateCommand(deps?: UpdateDeps): CommandModule;
export const updateCommand: CommandModule = createUpdateCommand();
```
- **Defaults, resolved in the action:** `templatesDir()` (C3), and the package version via a private `readPackageVersion()` that reads `path.join(findPackageRoot(), "package.json")`. Do **not** import `VERSION` from `../program.js`. That is a runtime import cycle, and it throws a TDZ ReferenceError because `program.ts` imports this module before its `const VERSION` initialises.
- **Algorithm:**
  1. Set up:
     - `root = findRepoRoot(ctx.cwd)`.
     - `{ config } = await loadConfig(root)`. `E_CONFIG_SYNTAX` propagates (exit 1).
     - `paths = resolvePaths(root, config)`.
  2. `manifest = await readManifest(paths.manifestFile)`. If it is `null`, throw `new WikeeperError(ExitCode.ERROR, "not_initialised", "not initialised — run wikeeper init")`.
  3. Build the package set from `listTemplateFiles("system", deps.templatesDir)` (open decision 2). Map each `system/<rest>`:
     - to the manifest path `.wiki/system/<rest>` (posix);
     - to the destination path `path.join(paths.systemDir, ...rest.split("/"))`.

     The old set is `manifest.files` filtered to `kind === "system"`, keyed by `path`.
  4. **Safety pre-pass, before any write.** Every destination path and every old entry's absolute path must satisfy `isInside(paths.systemDir, p)` and must not equal `paths.manifestFile`. Otherwise throw `WikeeperError(ERROR, "unsafe_path", …)`; nothing is written.
     - `isInside` is a private helper: `rel = path.relative(parent, child)`; inside means `rel !== ""`, `rel !== ".."`, `!rel.startsWith(".." + path.sep)` and `!path.isAbsolute(rel)`.
  5. For each package file, in sorted order, compute `newHash = await sha256File(src)` and `st = lstat(dest)`, then:

     | Local state | Action | Listed in |
     |---|---|---|
     | ENOENT | `copyTemplate` | `added` if not in the old set; else `replaced` (restores a deleted file) |
     | Not a regular file (directory or symlink) | `rename(dest, bak)`, then copy. Never write through a link. | `replaced`/`added`, `backed_up`, plus a warning |
     | `cur === newHash` | No write | — |
     | In the old set and `cur === old.sha256` | `copyTemplate` | `replaced` |
     | Otherwise: edited locally, or an unmanaged file at a new package path | Back up, then `copyTemplate` | `replaced`/`added`, `backed_up`, plus the warning `"<rel> was edited locally; saved as <bak rel>"` |
  6. **Dropped entries** are old entries not in the package set.
     - If the file is absent, drop the entry silently.
     - Otherwise, if the hash differs from `old.sha256`, back it up first (with a warning). Then `rm(abs, { force: true })` and add the path to `removed`.
     - Then prune emptied parents: `rmdir` up to, but not including, `systemDir`. Stop on ENOTEMPTY, EEXIST or ENOENT.
  7. Rewrite the manifest:
     - `manifest.files = [...non-system entries unchanged, ...package files as { path, sha256: newHash, kind: "system" }]`.
     - Set `package_version`.
     - `await writeManifest(manifest, paths.manifestFile)`.
  8. Run the integrations:
     - Call `runIntegrations("update", { root, paths, config, options: { …run, manifest, templatesDir, packageVersion } })`.
     - Call `writeManifest` again; it does not write when the bytes are unchanged.
     - Merge the results: `created` → `added`, `replaced` → `replaced`, `removed` → `removed`, `warnings` → `warnings`.
  9. Sort every list in code-unit order. Call `emitResult(ctx, { command: "update", data, warnings: data.warnings, message })`. The message is `updated: N replaced, M added, K removed` or `already up to date`.
- **Backups:**
  - The name is `<dest>.bak-<formatBackupStamp(now())>`. On a collision, append `-1`, `-2`, and so on.
  - Write with `copyFile(dest, bak, fs.constants.COPYFILE_EXCL)` in a loop that catches EEXIST (no TOCTOU).
  - The stamp contains no `:`, which keeps backup names legal on Windows.
- **Tests:**
  - **Fixture builder, local to each test file.** No shared helper file exists in §3.1. Build the repo in `mkdtemp(path.join(os.tmpdir(), "wikeeper-upd-"))`:
    - `.git/`;
    - `.wiki/system/{SETUP.md, WIKI.md}` containing `"v1\n"`;
    - `.wiki/{config.yml, kb_instructions.md, me.md, index.md}`;
    - `.wiki/pages/WIKI.md`, which has the same basename as a system file (EPIC-001 safety rule);
    - `manifest.json`, written as JSON with `createHash("sha256")` hashes. It must not depend on 001-04's `init` body.
  - **Template fixture:** a second temp directory holding `system/{SETUP.md, WIKI.md = "v2\n", profiles/management.md}`.
  - **Driving the command:**
    - Call `runCli(["update","--json"], { commands: [createUpdateCommand({ templatesDir, packageVersion: "9.9.9", now: () => new Date(Date.UTC(2026,9,16,12)) })], io: { cwd, stdout, stderr, stdin: Readable.from([]) } })`.
    - Assert the returned code and `JSON.parse` of the stdout line.
    - Call `beforeEach(resetIntegrations)`, then `registerIntegration({ name: "test", update: vi.fn() })`.
  - **Red scenarios:**
    1. `WIKI.md` is `"v2\n"`, `profiles/management.md` exists, and the manifest has `package_version` `"9.9.9"` plus the new hashes. The handler ran once with `ctx.paths.systemDir === path.join(root, ".wiki", "system")`.
    2. Edited `WIKI.md` → `.wiki/system/WIKI.md.bak-20261016120000` holds the edit, `WIKI.md` is `"v2\n"`, and `warnings` names `WIKI.md`.
    3. A template set without `SETUP.md` → the file is gone and the manifest entry is gone.
    4. Hash every file outside `.wiki/system/` before and after → equal.
    5. No manifest → exit 1, and the message contains "run wikeeper init".
  - **Unit tests (≥2):**
    - A no-op update: every list is empty, and the manifest bytes and `mtimeMs` are unchanged.
    - A pre-existing `.bak-<stamp>` → the backup gets `-1`.
    - `formatBackupStamp`.
- **Windows:**
  - Convert between posix and OS paths only via `split("/")` / `toPosixRelative`.
  - Write fixtures with an explicit `"\n"`.
  - Never compare paths with a string `startsWith`; use `isInside`.
- **Risks:**
  - The import cycle and TDZ issue (above).
  - Writing through a user symlink: handled by the `lstat` row in step 5.
  - Without open decision 2, `listTemplateFiles` cannot read a fixture template set.

### STORY-001-06 — `wikeeper remove` and `--purge`
STORY-001-06 advances the goal by deleting every core-owned file and the `.gitignore` block in reverse order, keeping knowledge unless a typed confirmation is given, so that after `remove` no wikeeper file or block remains (Goal check 3).
- **Files (§3.1):**
  - `src/commands/remove.ts` (new).
  - `src/core/gitignore.ts`: append `GitignoreStripStatus` and `stripManagedBlock` after 001-04's code; touch nothing else.
  - `test/remove.test.ts` (new). The `stripManagedBlock` unit tests live here, not in `test/gitignore.test.ts`, which 001-04 owns.
  - `src/program.ts`.
  - QA-Red writes `test/remove.red.node.test.ts`.
- **`src/program.ts`:**
  - Add `import { removeCommand } from "./commands/remove.js";` to the command-import region.
  - Append `  removeCommand,` as the last element of `defaultCommands`.
- **Exports:**
  - `RemoveResult { removed: string[]; kept: string[]; purged: boolean }`
  - `CONFIRM_WORD = "wikeeper"`
  - `removeCommand: CommandModule`
  - Options: `.option("--purge")`, `.option("--confirm <word>")`.
- **Algorithm:**
  1. Set root, config and paths as in 001-05 step 1.
  2. Read the manifest. If it is `null`, throw the same `not_initialised` error as 001-05.
  3. **Confirmation, before anything runs.** Integrations are not called and nothing is deleted when it fails. This applies only with `--purge`; `--confirm` without `--purge` is ignored.
     - `--confirm` given and not equal to `"wikeeper"` → `WikeeperError(ExitCode.ERROR, "confirmation_mismatch", "confirmation did not match \"wikeeper\"; nothing was removed")`.
     - No `--confirm` and not interactive → `WikeeperError(ExitCode.NEEDS_INPUT, "needs_input", "remove --purge deletes the wiki: re-run with --confirm wikeeper")`.
     - Interactive:
       - Write the prompt to `ctx.stderr`.
       - Read the first line with `createInterface({ input: ctx.stdin, terminal: false })` from `node:readline/promises`, via `for await … break`. EOF counts as `""`.
       - Call `rl.close()`, then `trim()` the answer.
       - A mismatch raises the same `confirmation_mismatch` error.
  4. **Safety pre-pass.** Core targets are the manifest entries of kind `system` or `file`. Each must satisfy `isInside(paths.wikiDir, abs)`; otherwise throw `unsafe_path` before any deletion.
  5. Run `r = await runIntegrations("remove", ctx)` first. It is the reverse of init, which runs integrations last. If a handler throws, the manifest is still intact, so a re-run can finish.
  6. Delete the core files in reverse path order with `rm(abs, { force: true })`. Only files that existed go into `removed`. **Never** unlink an entry of an integration kind (a `block` path is `AGENTS.md`).
  7. **`.gitignore`:**
     - Read `<root>/.gitignore`; on ENOENT, skip.
     - Decode with `TextDecoder("utf-8", { fatal: true, ignoreBOM: true })`. Invalid UTF-8 → a warning, and the file is left as is.
     - `stripped`:
       - If `text.trim() === ""` and the `gitignore` entry has `created === true`, unlink the file and add `.gitignore` to `removed`.
       - Otherwise write the remainder.
     - `malformed`: add the warning `.gitignore has a wikeeper start marker without an end marker; left unchanged`.
  8. Delete `paths.manifestFile` with `rm(…, { force: true })`. Then `rmdir` the directories under `systemDir`, deepest first, then `systemDir` itself. ENOTEMPTY or EEXIST means keep: leftover files such as `.bak-*` go to `kept`.
  9. **Purge.**
     - Run `rm(paths.wikiDir, { recursive: true, force: true, maxRetries: 3 })`.
     - If `contentDir` is outside `wikiDir`:
       - Delete only the wikeeper content entries: `pagesDir`, `rawDir`, `logDir`, `indexFile` and `contentDir/log.md`. Each must satisfy `isInside(contentDir, ·)`.
       - Then `rmdir(contentDir)`, only when `contentDir !== root`. ENOTEMPTY puts `contentDir` in `kept`.
     - Never run `rm -rf` on `contentDir`. `content_dir: docs` can hold user files, and `content_dir: "."` makes `contentDir === root`, which passes M1's containment check.
  10. **`kept` (default remove):** every path that exists among `configFile`, `kbInstructions`, `meFile`, `indexFile`, `pagesDir`, `rawDir` and `logDir`, as posix paths with no trailing `/`, plus the leftovers from step 8.
  11. Merge `r.removed`, `r.kept` and `r.warnings`. Sort, then call `emitResult({ command: "remove", data: { removed, kept, purged }, warnings })`.
- **`stripManagedBlock`:**
  - Split the text into lines, keeping each line's terminator.
  - Find the first line equal to `GITIGNORE_BLOCK_START`, comparing without the trailing `\r`. On line 0, ignore a leading U+FEFF and keep it in the output.
  - Find the first later line equal to `GITIGNORE_BLOCK_END`.
  - Remove the START…END lines together with the END line's terminator. Loop until no block remains.
  - Return `absent` when there is no START line, and `malformed` when START has no END; in both cases the text is unchanged.
  - Use only the exported constants, never literal marker strings.
- **Tests:**
  - **Fixture:** the same in-code builder as 001-05, plus a `gitignore` manifest entry and `.wiki/pages/a.md`, `.wiki/raw/x.txt` and `.wiki/log/1.md`.
  - **Red scenarios:**
    1. `remove --json`: `.wiki/system/` is gone; the user files are byte-identical; the `remove` handler ran once; `purged` is false.
    2. `"node_modules/\n" + block + "dist/\n"` → `.gitignore` is `"node_modules/\ndist/\n"`.
    3. With `content_dir: wiki` and a sibling `notes.txt`, `--purge --confirm wikeeper` → `.wiki/` and `wiki/` are gone and `notes.txt` remains.
    4. Outline, with `stdin` having no `isTTY` and the args `--purge --json`:
       - no confirm flag → exit 5;
       - `--confirm yes` → exit 1;
       - in both rows, the recursive file listing is equal before and after, and the handler is not called.
    5. No manifest → exit 1, and the message contains "not initialised".
  - **Unit tests (≥2):**
    - `stripManagedBlock` on: surrounding text; a block only; absent; malformed; CRLF built inline (`"a\r\n# >>> wikeeper >>>\r\n…"`); a BOM.
    - The interactive path with `stdin = Object.assign(Readable.from(["wikeeper\n"]), { isTTY: true })` → `purged: true`; a wrong word → exit 1.
    - A created-and-emptied `.gitignore` is deleted.
    - Round-trip against `applyManagedBlock`; this goes green only after 001-04 merges.
- **Windows:**
  - Use `maxRetries` on `rm` (EBUSY/EPERM from AV scanners).
  - `rmdir` reports a non-empty directory as ENOTEMPTY or EEXIST; handle both.
  - Never compose paths from strings: `path.relative` compares case-insensitively on win32.
  - Keep CRLF and BOM fixtures inline; never commit them as files (`eol=lf`).
- **Risks:**
  - A core-kind filter bug that deletes agent files. Step 6 plus a test where a `kind: "block"` entry for `AGENTS.md` survives core removal.
  - Purge with `content_dir: "."`. Add a test asserting the repo root and `notes.txt` survive.

### STORY-001-07 — `wikeeper doctor` and setup state
STORY-001-07 advances the goal by making `doctor --json` exit 0 on a healthy install and exit 1 with a fix line when something breaks. Integration checks such as a deleted WIKI block (002-04) reach the agent through the same report (Goal check 4).
- **Files (§3.1):** `src/commands/doctor.ts`, `src/commands/setup.ts`, `test/doctor.test.ts`, `test/setup.test.ts` (all new), and `src/program.ts`. QA-Red writes `test/doctor.red.node.test.ts` and `test/setup.red.node.test.ts`.
- **`src/program.ts`.** This is the only story that registers two commands.
  - Imports:
    - `import { doctorCommand } from "./commands/doctor.js";`
    - `import { setupCommand } from "./commands/setup.js";`
  - Append `  doctorCommand,` and `  setupCommand,` as the last two elements of `defaultCommands`.
- **Exports (`doctor.ts`):**
```ts
export interface DoctorResult { checks: DoctorCheck[]; errors: number; warnings: number }   // DoctorCheck from ../core/integrations.js
export const MIN_NODE_VERSION = "22.12.0";
export function compareVersions(a: string, b: string): number | null;   // /^v?(\d+)\.(\d+)\.(\d+)/; null if unparseable
export function checkNodeVersion(version: string): DoctorCheck;
export function runDoctor(root: string, run: Pick<IntegrationOptions, "flags" | "json" | "interactive" | "io">, deps?: { nodeVersion?: string }): Promise<DoctorResult>;
export function createDoctorCommand(deps?: { nodeVersion?: string }): CommandModule;   // nodeVersion defaults to process.versions.node
export const doctorCommand: CommandModule = createDoctorCommand();
```
- **Checks.** They run in this fixed order, each wrapped in `try`/`catch`. An unexpected throw becomes `{ id, severity: "error", message: "check failed: <msg>" }`, and doctor never stops early.

  | id | ok | warning | error | fix |
  |---|---|---|---|---|
  | `node-version` | `Node <v>` | unparseable version | `Node <v> is older than 22.12.0` | `install Node.js 22.12 or newer` |
  | `wiki-initialised` | manifest found | — | `readManifest` → `null`: `wiki is not initialised`; `E_MANIFEST_INVALID`: `manifest is invalid: <msg>` | `run wikeeper init` / `delete .wiki/system/manifest.json and run wikeeper init` |
  | `config-valid` (`file: ".wiki/config.yml"`) | no issues | warnings only: `warnings.map(formatConfigIssue).join("; ")` | the config file is missing; `E_CONFIG_SYNTAX` (its message); or `errors.map(formatConfigIssue).join("; ")` | `run wikeeper init` / `fix the YAML syntax in .wiki/config.yml` / `edit .wiki/config.yml` |
  | `manifest-drift` | `N package files match the manifest` | any `modified` | any `missing`; or, when not initialised, `not checked: wiki is not initialised` | `run wikeeper update` (it backs up edits) / `run wikeeper init` |
  | integration checks | as returned | | | |

  - `manifest-drift` grades only `diffManifest(...)` rows with `sha256 !== null`. Null-hash kinds (block, link, dir, hook, rule) belong to the integration checks. Its message is `missing: a, b; modified: c`.
  - Integration checks come from `(await runIntegrations("doctor", ctx)).checks`, appended in the order returned, never filtered or sorted. In that context:
    - `config` is the loaded config, or `structuredClone(DEFAULT_CONFIG)` after a syntax error;
    - `options.manifest` is the manifest, or the empty manifest.
  - Detect a missing config file with `fs.stat(paths.configFile)`, because `loadConfig` returns the defaults silently when the file is absent.
- **Exit and output:**
  - `errors` counts severity `error`; `warnings` counts severity `warning`. `ok` and `info` are not counted.
  - Call `emitResult(ctx, { command: "doctor", data: { checks, errors, warnings }, warnings: [], message })`, then `ctx.setExitCode(errors > 0 ? ExitCode.ERROR : ExitCode.OK)`.
  - Never throw for findings (M1 risk 7). Pass `warnings: []` so the human output does not print them twice.
  - Human lines: `[ok]|[info]|[warn]|[error] <id>: <message>`, an optional `  fix: <fix>` line, and the closing line `<e> errors, <w> warnings`.
