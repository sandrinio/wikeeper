## §2. How `init` and `update` treat the blocks

**init never refreshes a block.**
- The agents integration's `init` (`src/agents/index.ts:273–306`) reads the template with `loadBlock` (`:109–111`). For each target from `resolveTargets` (`src/agents/detect.ts:69–84`), it calls `injectIntoFile` (`index.ts:291–295`).
- `injectBlock` returns `skipped` when the file already contains `<!-- WIKI:START` (`src/agents/inject.ts:51–53`). So `init` writes the block only into a file without one, and a 0.3.0 project keeps its old block under `init`.
- Each target gets a manifest entry `{ kind: "block", path }` (`index.ts:296–297`). That entry is what `update` later walks.
- With only `CLAUDE.md` and `--agents claude`, the target is `CLAUDE.md`. With only `AGENTS.md` and `--agents codex`, it is `AGENTS.md`. With only `CLAUDE.md` and `--agents claude,codex`, `AGENTS.md` is created for codex (`detect.ts:79–81`).

**update refreshes recognised blocks.**
- `runUpdate` calls `runIntegrations("update", { …, templatesDir })` (`src/commands/update.ts:182–190`). The agents `update` (`index.ts:308–318`) then calls `refreshBlocks` (`:316`).
- `refreshBlocks` (`:133–147`) loads the current template and, for every manifest `block` entry, calls `refreshInFile(path, block, SHIPPED_BLOCKS)` (`:139`). The manifest is all it uses, so CLAUDE.md and AGENTS.md are handled the same way.
- `refreshBlock` (`inject.ts:147–169`) works in this order:
  1. normalise the template (`:152`, `normaliseBlock` `:142–144`: no BOM, LF, no trailing breaks);
  2. exactly one START and an END, or the result is `absent` or `malformed` (`:154–160`);
  3. if the normalised current block equals the template, `current`, with no write (`:163`);
  4. if it equals no `SHIPPED_BLOCKS` entry, `edited`, with no write (`:164`);
  5. otherwise replace it with the template in the file's own EOL, keeping the BOM and the bytes outside the block (`:165–168`).
- The results reach the report as follows:
  - `refreshed` becomes `replaced: "<path>#wiki-block"` (`index.ts:139`);
  - `edited` becomes the warning `"<path>: WIKI block was edited, so update left it unchanged; to get the current block, delete it from its WIKI:START line to its WIKI:END line and run wikeeper init"` (`:140–143`);
  - `not-utf8` becomes its own warning (`:144`).
